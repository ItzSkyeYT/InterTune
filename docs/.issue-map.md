the other half of it: candidates that were investigated and rejected, so they do not get
re-litigated. 680 of the last 843 page views came from github.com, mostly upstream's tracker,
so a wrong claim here converts straight into an install that reproduces the bug and an issue
this repo has said it will not support. Default to not claiming the fix.

## Standing caveats for any future 403 claim

- The resolution loop still tries `MAIN_CLIENT` (`ANDROID_VR_NO_AUTH`) first, and `validateStatus`
  is a bare `HEAD` that a capped url passes. `VISIONOS` is reached because the main client fails
  outright, not because the code forces it. That is an empirical dependency, not a guarantee.
- Verification is one device and one account. No third party has confirmed anything except
  rii2609 on #1282.
- `docs/403.md` dates the gate to August 2026, but upstream's own source has carried
  `IOS, // recent api changes produce error 403 after 30 seconds` since September 2025. Any
  claim on a pre-August-2026 report inherits that contradiction.
