# 994 — App crash upon removing downloaded song

**Labels:** bug · **State:** blocked · **Last scored:** 2026-09-02

## What breaks
Removing a download from the liked-songs / artist / album screens crashes the app. The removal
itself succeeds — the song does leave the library — so the crash is after the delete, likely in
whatever recomposes off the download state.

## Where
Not located. "After a successful delete, on the observing screen" is as far as the report gets;
that spans the download manager, the download DAO flow, and three screens.

## Evidence present / missing
- **Present:** a useful detail — the delete succeeds and the crash follows, which points away
  from the delete call itself.
- **Missing:** logs (`Not provided`), stack trace, second reporter, the `confirmed` label.
  Device: Samsung a54 / One UI 7 / Android 15, version 0.10.0.

## Likely fix
Unknown without a stack trace.

## The single blocker
**No stack trace.** For a crash this is decisive — the report gives a symptom and a screen set,
nothing that names a frame.

## What would raise the score
A DEBUG logcat. With one, this would likely localize well, since the trigger is a single
deterministic user action.
